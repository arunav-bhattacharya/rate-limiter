A) Executive Summary (Corrected)
================================================================================

Overall best default for the stated workloads (500 TPS near-term + 500k @ 100 TPS long-horizon):
- V5 is the safer default under current settings, unless measurements show RL_WNDW_CT row-update lock waits are a major bottleneck.

Why this correction:
- V6 hot path removes counter UPDATE contention, but adds:
  - one extra per-request COUNT transaction,
  - plus repeated scheduler MERGE/COUNT load across pods.

- Proximity behavior is the same picker in both; V6 occupancy hints are staler by design.

   src/main/kotlin/com/ratelimiter/repo/WindowSlotCounterRepository.kt:141-143,
   src/main/kotlin/com/ratelimiter/slot/WindowCounterRefreshScheduler.kt:34-40]

- Correctness is nuanced:
  - V5: no explicit maxSlots check at claim time.
  - V6: has soft guard check, but it is non-atomic (COUNT then INSERT race).

When recommendation changes:
- If measured V5 counter-row lock waits are high enough to dominate p95/p99 latency,

H) Quant Note: V5 Counter Contention Math (explicit sensitivity)
================================================================================

Goal: quantify when V5 update contention is mild vs severe.

Definitions:
- lambda_row = 500 * p_hot  (arrivals/sec to hottest window row)
- h = lock-hold/service time per update txn (sec)
- mu = 1/h
- rho = lambda_row / mu = lambda_row * h

Input hints:
- Config comments indicate typical rate-limiter DB hold times ~3-10ms.
  [src/main/resources/application.yaml:45-47]

If p_hot ~ 6.45% (linear proximity weight with 30 windows, equal occupancy),
then lambda_row ~ 32.3/s.
- h=3ms => rho=0.097
- h=5ms => rho=0.161
- h=10ms => rho=0.323
=> usually manageable.

If traffic concentrates (example p_hot=25%):
- lambda_row=125/s
- h=5ms => rho=0.625
=> queueing starts to matter.

If p_hot=35%:
- lambda_row=175/s
- h=5ms => rho=0.875
=> significant wait inflation.

Takeaway:
- V5 contention is not automatically severe.
- It becomes severe only when row concentration and/or hold time push rho near 1.
- Therefore a measured decision is required; assumptions alone are insufficient.
